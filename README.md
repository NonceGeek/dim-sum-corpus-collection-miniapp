# dim-sum-corpus-collection-miniapp

## 本地运行

1. 安装依赖：`npm ci`。
2. 在微信开发者工具中导入本仓库根目录，使用 `project.config.json` 中配置的 AppID；微信账号需有对应项目权限。
3. 在工具菜单执行“构建 npm”，然后编译。项目依赖 TDesign，未构建 npm 时组件无法加载。
4. 接口环境见 `miniprogram/config/setting.ts`，默认连接线上 API。投稿会写入对应环境，请使用测试账号与活动。

## 视频号作品接入（Issue #474）

所有投稿均可额外关联一条视频号作品，不受活动媒体类型限制。沿用现有 TDesign 弹层、按钮、主题与确认对话框；输入两个 ID 后可打开作品检查，返回继续填写，封面选填。保存关联不代表本人归属认证。

关联与本地视频、图片、录音共存，不替代活动要求的正文媒体。底部“预览”展示当前草稿，返回编辑保留输入，不提交投稿。详情页点击进入视频号；瀑布流和活动精选页支持作品标记与无封面卡片。

后端需部署支持 `channelVideo` 的版本（dim-sum-app PR #485）。预检必须返回 `requiresManualReview: true` 和 `channelVideoChecked: false`，否则客户端保留输入并阻止提交，避免旧接口忽略关联。扫码运营审核入口未接入。

## 验证

- `npm test`：运行实际页面逻辑的隔离行为测试，微信 API 和请求层使用替身；不向线上写入测试数据。
- `npm run typecheck`：当前仓库仍有既有类型错误，本次基线比较无新增错误，不能视为全量通过。
- 仍需在开发者工具检查编译、深浅色主题、键盘与弹层，以及 iOS / Android 真实作品跳转。页面存活期间返回保留表单；尚未实现进程被系统回收后的草稿恢复。


## 媒体与封面

图片与视频分别选择，本地视频与额外的视频号关联分区展示。封面区域支持单独上传、更换和恢复默认。默认顺序为第一张正文图片、视频缩略图、类型占位；用户指定或编辑回填的已有封面优先。视频缩略图保存在视频 `metadata.thumbnailUrl`，不加入正文图片；最终封面通过已有 `coverUrl` 提交，并参与图片预检。旧稿回填保留接口返回的封面，用户可点“恢复默认”重新计算。仅有封面不算投稿内容。

首页 Feed 当前未提供本地视频类型字段，无法确定类型且无封面的旧稿使用通用作品占位；有完整媒体数据的列表区分视频、音频和图片。没有改动后端接口或活动校验规则。
